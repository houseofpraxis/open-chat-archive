# OpenWebUI JSON adapter

Adapter version 0.1.3 accepts the documented JSON export array in either the current wrapper form (`chat` containing chat data) or the legacy form where each array element is chat data. It also recognizes the documented current wrapper topology where a boolean field sorts before the `chat` object. Recognition uses only shape-only aliases, types, and cardinalities. The adapter retains every `history.messages` node, including inactive branches, validates reciprocal `parentId`/`childrenIds` links and rejects dangling, cyclic, and inconsistent graphs. A connected nonbranching graph (including a singleton) is canonically `linear`; one connected branching graph is `tree`. Multiple explicit roots, including all-isolated nodes, are a validated source forest: v0.1 records canonical `thread_shape=unknown` and the adapter extension `thread_shape=forest`; `forest` is not a v0.1 canonical value. `history.currentId` is retained as source-selected active-node evidence, never used to discard branches; it need not be a leaf, final response, or latest message. Its lifecycle event keeps the stable logical-key suffix `:active-leaf` while reporting `detail=active_node`; it is `completed` only when its source `done` is exactly `true`, otherwise `unknown`. Message visibility is conservative by role: tools are `tool_traffic`, system/developer nodes are `control`, unknown roles are `unknown`, and ordinary user/assistant messages are `user_visible`. Title, RFC 3339 timestamps converted from unix epochs, primary model, `thread_shape`, and `active_message_id` are canonical when the source is canonical-safe. Node role/content/model/done/timestamp/context plus wrapper models/options/meta/pinning/folder/timestamps remain namespaced extensions. Message `source_ordinal` follows `childrenIds` graph order. Parent links include `sibling_index`. Evidence uses JSON Pointers; projected fields are `mapped` in the coverage ledger. Wrapper and nested chat metadata are both retained if both occur.

This adapter alone has fixed ceilings of 128 MiB for its regular source read and 100,000 structural nodes for its batch profile; generic adapter defaults are unchanged. It parses source JSON with a source-only finite-decimal representation. Decimal/exponent tokens remain exactly in the retained source artifact and are never converted to floats or text; metadata and rich JSON content that contains one is omitted from canonical records, while canonical-safe metadata and string message content remain mapped.

Native top-level IDs are stable within the configured source scope. When absent, the chat array ordinal supplies a deterministic `artifact-local` key marked `same-artifact-only`; no cross-export stability is claimed. Every mapped semantic record has a parsed observation bound to byte range `0..source_length` of the exact source artifact, which preserves remaining and unsupported fields.

Format facts were inspected from the read-only upstream snapshot pinned at commit `2a960a59fe1dbbd35282f0556b3666d81102e781`, especially `backend/open_webui/models/chats.py` and `src/lib/utils/index.ts`, without copying implementation. Adapter 0.1.2 was independently checked against one authorized bounded real export in a deleted mode-0700 temporary archive: recognition, exact-byte retention, archive validation, quiet operation, source-number isolation, and identical-import semantic stability passed. This is bounded compatibility evidence, not a claim of exhaustive historical or future OpenWebUI support.
