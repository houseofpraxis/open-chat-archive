# Claude Code JSONL adapter

`ClaudeCodeAdapter` accepts one regular, non-symlink session JSONL file using the locally observed Claude Code **2.1.251** vocabulary. It maps user/assistant entries, string or block content, parent UUID relationships when both endpoints are messages, assistant model responses, tool uses/results, reported usage (including cache read/write token fields), and `system` `compact_boundary` lifecycle evidence. A `user` entry containing only `tool_result` blocks is mapped as `tool`/`tool_traffic`; reasoning-only content is `exported_reasoning` and mixed reasoning plus visible content is `unknown`. Assistant model-response status is `unknown`: this baseline does not map an explicit completion indicator. Known timestamps/model/compaction metadata stay under the adapter namespace; unknown entry types and fields remain exactly in the retained source artifact. Tool status, model IDs, and usage are emitted only when present in the input.

The native `sessionId` and UUIDs provide stable identities within a configured source scope. Auxiliary preserved-only records may omit `sessionId`; mapped user/assistant messages and `system` `compact_boundary` records must retain an explicit non-empty `sessionId` matching the transcript session. A compact boundary without a UUID is explicitly artifact-local and same-artifact-only. Every mapped semantic record has a parsed observation bound to byte range `0..source_length` of the exact retained JSONL artifact. It does not scan directories, subagents, or other session files; those variants are unsupported rather than silently discovered.

Value-free/full-data local validation covered authorized local Claude Code 2.1.251 transcripts after this correction. This is evidence of local compatibility, not exhaustive format support.
