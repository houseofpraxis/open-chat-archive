# Codex rollout JSONL adapter

The explicit `codex` adapter imports one regular, non-symlink JSONL file in the Codex CLI 0.147.0 rollout container. It does not scan directories. Its implementation vocabulary was reviewed clean-room from the pinned upstream Rust declarations at tag `rust-v0.147.0`, commit `be6e8eac029b183056b7e4402879f15d2c85f61b`, specifically the rollout wrapper and protocol/model type declarations. No upstream implementation code was copied, and this document does not imply OpenAI endorsement.

Each line is a `RolloutLine`: nonempty `timestamp`, optional nonnegative integer `ordinal`, and flattened `{type, payload}`. Supported top-level types are `session_meta`, `response_item`, `inter_agent_communication`, `inter_agent_communication_metadata`, `compacted`, `turn_context`, `world_state`, `event_msg`, and the observed payload-free `token_usage_record` form. A single session metadata item is required. When `session_id` is a nonempty string it is the session identity; if it is absent, nonempty `id` is the documented legacy fallback. The two fields may differ; both are retained in the adapter namespace when present. Unsupported top-level types, unknown response-item types, unknown event-message types, malformed mapped records, duplicate metadata, duplicate nonempty `ResponseItem.id` values, and duplicate call identities for the same mapped tool direction are rejected with fixed codes.

The current response vocabulary allowlisted by this release is `additional_tools`, `message`, `agent_message`, `reasoning`, `local_shell_call`, `function_call`, `tool_search_call`, `function_call_output`, `custom_tool_call`, `custom_tool_call_output`, `tool_search_output`, `web_search_call`, `image_generation_call`, `compaction`, `compaction_trigger`, and `context_compaction`. The serialized alias `compaction_summary` is accepted as `compaction`. The pinned `EventMsg` vocabulary is also explicitly allowlisted; only its directly representable events are projected. The observed `thread_settings_applied` event and `token_usage_record` top-level record are accepted; integer fields from `token_usage_record.payload.usage` map as a usage event, correlated to a nonempty `response_id` when present. Other token usage summaries and metadata remain source-only. Known but unmapped response, inter-agent, world-state, and event records remain exactly preserved in the source artifact.

Plain `input_text` and `output_text` response messages map to canonical messages. User, assistant, system, developer, and tool roles retain their direct roles; system/developer are control and tool is tool traffic. Plain reasoning summary/content maps to assistant reasoning messages with `exported_reasoning`; encrypted, image/audio, and other unsupported content remains source-only. Native item IDs, call IDs, turns, response IDs, and string compaction windows establish stable adapter-scoped identities:

- session: `session_id`, else `id`
- message/reasoning: `message:{id}` / `reasoning:{id}`
- function/custom tools: `function-call:{call_id}`, `function-call-output:{call_id}`, `custom-tool-call:{call_id}`, `custom-tool-call-output:{call_id}`
- exec/MCP/web/dynamic: `exec-begin:{call_id}`, `exec-end:{call_id}`, `mcp-begin:{call_id}`, `mcp-end:{call_id}`, `web-begin:{call_id}`, `web-end:{call_id}`, `dynamic-request:{call_id}`, `dynamic-response:{call_id}`
- raw usage: `raw-usage:{response_id}`
- compaction: `compact:{window_id}` when `window_id` is a nonempty string

A legacy numeric compacted `window_id` is treated as `window_number`, not as an identity. Missing native IDs use explicitly marked artifact-local, same-artifact-only fallbacks. `source_ordinal` is always the zero-based JSONL line index, never the optional persisted ordinal, because the archive schema requires that field. Native `entity_id` values remain stable when unmapped lines are inserted; `revision_id` may change because `source_ordinal` is part of the semantic body.

Task/turn start and completion supply turns and lifecycle facts. Direct start/completion/duration integers and each mapped record's wrapper timestamp are retained in adapter-namespace extensions when present. A response becomes a `model_response` only where an applicable explicit `turn_context` supplies a nonempty model and session metadata supplies a nonempty provider; it is otherwise not inferred. Function/custom calls and results, exec command begin/end, MCP begin/end, web-search begin/end, and dynamic-tool request/response evidence map when their canonical-safe required fields are present. Canonical `tool_namespace` is always `org.open-chat-archive.codex.tools` or `org.open-chat-archive.codex.mcp`; a source namespace string is retained only as adapter metadata. Begin events never claim success. MCP `result.Ok` maps to `ok` unless `is_error`/`isError` is true; `result.Err` maps to `error`. Raw-response usage maps integer input/output/total/cache/reasoning metrics and is correlated by `response_id`. Token-count total versus last usage remains namespaced and artifact-local. Compaction and context-compacted events map lifecycle evidence.

The complete source bytes are retained as the source artifact, and every emitted semantic body/extension is observed against its whole byte range. In adapter patch release 0.1.3, direct session metadata, turn, text-message, reasoning-message, and existing event observations also carry their precise physical JSONL line. Validation shares one strict source-safe NDJSON parse per source artifact within a batch when checking JSONL lines and JSON pointers; this is a validation cache, not a claim that every semantic projection can be universally validated from a line coordinate. Source JSON may contain finite decimal or exponent tokens in metadata such as rate limits. The adapter uses the source-only parser to retain those tokens as non-canonical wrappers; they are neither converted to floats nor emitted into records. Canonical JSON continues to forbid floats and does not accept the wrapper. Consequently, these decimal values remain recoverable only from the exact source unless a future canonical field has an explicit lossless string meaning. Structural profiling uses a Codex-specific 100,000-node ceiling; the generic writer default remains 10,000. Profiling runs before a new source object is stored.

Recognition uses only shape-only-v1 aliases, types, and cardinalities, and is only a conservative aid to explicit format selection. The source review establishes an implementation vocabulary, but compatibility evidence is bounded and not exhaustive: this adapter claims only the pinned declarations, wholly synthetic regression evidence, and a later independent no-disclosure local check when one is reported. It is not a claim of exhaustive historical or future Codex rollout support.
