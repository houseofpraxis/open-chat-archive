# Claude.ai account export adapter

`ClaudeAIAdapter` 0.1.2 accepts one regular, non-symlink `conversations.json`-style JSON file up to 64 MiB. It uses a fixed 500,000-node shape-profile ceiling for this adapter only; generic profiling defaults are unchanged. The source is an array of conversation objects with native `uuid`, optional `name`/timestamps, and `chat_messages`. Recognition accepts both the documented synthetic topology where the chat-messages array is the first opaque sorted field and the compatible account-wrapper topology where a nested object precedes it and shifts that array to the second field. It does not discover adjacent files. Human and assistant messages with UUIDs map to sessions and messages; text, reasoning/thinking, and code blocks map to content. Reasoning-only content is `exported_reasoning`; a mix of reasoning and visible content is conservatively `unknown`. Well-formed `tool_use` and `tool_result` blocks become tool events with `message_id` and per-session event ordinals. RFC 3339 conversation/message timestamps are projected onto canonical `created_at`/`updated_at`; native values also remain as observed adapter extensions. Sessions declare `thread_shape=linear`. Evidence uses JSON Pointers into the export array. Attachments, files, and attachment binaries are not claimed as present or copied.

The adapter's source parser retains finite decimal tokens only in the exact source artifact; it never converts them to floats or canonical text. Session/message metadata and tool input/output are projected only when recursively canonical-safe. A metadata value or tool block containing a source-only decimal is omitted from semantic records while remaining exact in the retained source artifact. Every mapped semantic record is bound by a parsed observation to byte range `0..source_length` of that artifact; unsupported fields remain available there. Native UUID identities are stable across reordered or expanded exports when the configured source scope is unchanged. ZIP is deliberately unsupported in this baseline: locally preprocess it to one verified JSON file before import; this version cannot preserve the outer ZIP.

Anthropic's public documentation confirms that account export is available but does not publish a stable object schema. Adapter 0.1.1 was independently checked against the `conversations.json` member of one authorized bounded real account export in a deleted mode-0700 temporary archive and then imported into an ignored owner-only local archive: recognition, exact-byte retention, archive validation, quiet operation, source-number isolation, and deterministic synthetic re-import passed. Adjacent export members remain outside this adapter. This is bounded compatibility evidence, not a claim of exhaustive historical or future Claude.ai support.
