# Data model

Every protected NDJSON envelope preserves its exact `identity` input: archive ID, record type, adapter namespace, identity scheme/version, operator-configured stable source scope, and adapter-declared logical key/native ID. `entity_id` is SHA-256 of canonical JSON for that block. Artifact digest, locator, path, batch, run, host, and import clocks are excluded. When no stable source key exists, adapters may declare `fallback.kind=artifact-local` and `stability=same-artifact-only`; the logical key may then use an artifact-local locator, and no cross-snapshot idempotency is claimed.

`revision_id` covers canonical semantic envelope content (`spec_version`, type, entity ID, sensitivity, protected identity, body, and semantic extensions). Observations are separate records. Storage paths are excluded only for typed source/artifact records, and importer clocks are excluded only from typed import controls; a semantic field is never excluded merely because its name resembles bookkeeping. An unchanged fact in a reordered or expanded full export therefore keeps both semantic IDs; changed content appends a revision. Source artifacts, observations, and immutable batches have separate identities.

An `observation` binds evidence to an exact subject entity/revision and JSON Pointer field paths. A binding covers that path and descendants, allowing ancestor coverage; multiple bindings allow mixed-source fields. Parsed/observed bindings require source artifact locations. JSON sources require a JSON Pointer; JSONL sources require a `jsonl_line`. A whole-artifact byte range may accompany those coordinates but is not sufficient alone. User assertions and context assertions retain distinct claim bases. Adding a source observation does not alter a semantic revision. Archive validation requires every semantic body leaf to be covered.

`proposal` records preserve parsed, user, context, or model suggestions with pending, approved, rejected, or unresolved status and exact evidence. Their subject names an exact entity and revision. Approved/rejected states record approver basis and time. Pending, rejected, and unresolved model proposals cannot populate canonical facts. A canonical `model_inferred` binding must reference an approved model-inference proposal for the same subject revision and field.

Session and message bodies may carry RFC 3339 `created_at`/`updated_at` and a `model` object (`provider`, `model_name`, optional `model_revision`) when the source supplies a canonical-safe value. Native epochs or product-specific model strings may also remain in namespaced extensions. A session may declare `thread_shape` as `linear`, `tree`, or `unknown`, and may name `active_message_id` when the source identifies a source-selected current message; it is not necessarily a leaf, final response, or latest message. `source_ordinal` is unique among records of the same type in the same session; it is a stable source coordinate, not display time. Events may name `message_id` of the issuing message. Relationships may carry `sibling_index` for ordered children.

Events have kind-discriminated payloads. Tool events preserve namespace/name, call/correlation IDs, arguments/results/errors as protected JSON or exact artifact references, and status. Model events preserve provider/model/revision, parameters or artifact, request/response references, finish reason, and status. Log and resource events point to exact artifact records; structured log metadata remains separate. Spans nest explicitly. Provider-reported usage retains token/cost fields plus namespaced unknown metrics. Sparse events omit unavailable data and never invent it. Content parts discriminate text/reasoning/code, JSON, and media/artifact references.

Canonical JSON uses sorted string keys, UTF-8, integers, booleans and null; floats and non-finite values are forbidden. Decimal metrics use strings.
